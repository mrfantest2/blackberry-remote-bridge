# Hardware, network and deployment audit — 2026-11-08

## Source and hardware
- GitHub `main` was `9327b48ff471d79770be286b92ec52b63e5560d5` and MASTER-PC working tree clean before this report.
- Torch 9810 is present on Steam Deck USB as `0fca:8004`.
- Barry read-only deviceinfo reports VM `7.0.1.40`, but `OS Version: 0.0.0.0`; **the exact installed handset OS is not confirmed**. Do not infer OS 7.1 from VM version.
- JDE 7.0 is a conservative target for BlackBerry OS 7.0; JDE 7.1 is appropriate only after confirming OS 7.1 or ensuring no newer APIs are referenced.
- Neither `rapc` nor `net_rim_api.jar` was found in inspected environments. No verified source for authentic legacy JDE binaries or signing keys has been established; do not execute repackaged third-party toolchains.

## HTTP 403 vs 404
- `GET https://s25.fantest.win/api/native/v1/status` from MASTER-PC and Steam Deck returned HTTP **404** with `Content-Type: application/json` in direct probes. Prior Python `urllib` probes returned **403**; these differing results are not interchangeable.
- Cloudflare response headers on Steam Deck: `server: cloudflare`, `cf-cache-status: DYNAMIC`, `cache-control: no-store`, `content-type: application/json; charset=utf-8`.
- Cloudflare zone `fantest.win` is active; zone Access application listing showed no app specifically targeting `s25.fantest.win`. This does **not** rule out zone rules, account policies, application middleware or origin authorization.
- Origin service routing and origin logs remain unverified. Do not change production routes or relax Cloudflare controls based solely on HTTP status.

## Legacy TLS
- Modern Steam Deck negotiated TLS 1.2 with ECDHE-ECDSA-CHACHA20-POLY1305 and validated the certificate. This **does not demonstrate** that BlackBerry OS 7 supports that cipher or current trust chain.
- No TLS downgrade, certificate-validation bypass, plain HTTP or global security exception is authorized. If compatibility fails, use a separately secured modern relay with device-specific authorization and validated TLS on each supported hop; test on actual hardware first.

## No-login experience
- A one-time user-approved pairing can issue a revocable, scoped credential for the BlackBerry device. Subsequent sessions should be automatic and protected by HTTPS, expiry, replay defense, revocation and explicit S25 authorization for sensitive actions.
- Do not expose public anonymous device control, embed shared secrets in GitHub or store control credentials in the Java source.

## Gate
- Native source and static tests exist; actual `COD` and `ALX` generation, signing, installation, network handshake and control are **blocked** by missing SDK, unknown handset OS version and absent backend contract.
